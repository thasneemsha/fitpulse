# Quality Assurance (QA) Plan

### Testing Objectives
The primary objective of the QA phase is to ensure the application is secure, free of critical defects, and provides a seamless user experience across devices.

##  Manual Test Cases

| Test ID | Scenario | Steps to Execute | Expected Result | Status |
| :--- | :--- | :--- | :--- | :--- |
| **TC-01** | User Registration | Submit a valid email and password to the register endpoint. | `201 Created` response; user appears in database. | Pass |
| **TC-02** | Duplicate Email | Register with an email already in the database. | `400 Bad Request` error displayed. | Pass |
| **TC-03** | Valid Login | Submit correct credentials. | `200 OK`; JWT token returned and stored in LocalStorage. | Pass |
| **TC-04** | Unauthorized Access | Access `/dashboard` without a JWT token. | User is redirected to the login page. | Pass |
| **TC-05** | Dynamic Workout Logging | Log a "Cardio" workout and a "Strength" workout. | `201 Created`; JSON details match the selected workout type. | Pass |
| **TC-06** | AI Insight Generation | Click "Generate" on the dashboard with 10+ workouts logged. | Text is generated by Gemini and rendered in the UI within 5 seconds. | Pass |
| **TC-07** | Responsive Layout | Open application on a 375px mobile viewport. | Grid layout collapses to a single column; no horizontal scrolling. | Pass |
| **TC-08** | CORS Verification | Attempt to access API from unauthorized origin. | Request blocked by browser/CORS middleware. | Pass |

## Future Automated Testing (Roadmap)
*   **Backend:** Implement `pytest` and `httpx` to achieve 80% code coverage on authentication and CRUD routes.
*   **Frontend:** Utilize `Playwright` to simulate user interactions (login, logging a workout, clicking the AI button) to ensure UI stability.
*   **CI/CD Integration:** Configure GitHub Actions to run tests automatically on every push to the `main` branch.
